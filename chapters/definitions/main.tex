\chapter{Formal foundations and datasets}
\label{chapter:definitions}
\input{abstract}

This chapter formalizes, in precise mathematical terms, the page, web article, template, and print article entities that \melody already manipulates natively as a feature of its production system (\secref{sec:basic-elements}). This formalization underlies every contribution developed in the remainder of this thesis.

\section{Core concepts and representations}
\subsection{Newspaper page ($\page$)}.
\label{sec:page-definition}

A page $\page$ (\figref{fig:page}) defines the empty canvas and its physical boundaries. Formally, $\page$ is represented as a tuple containing the structural dimensions:
\begin{equation}
\page = \langle \Wpage, \Hpage, \mtop, \mbottom, \mleft, \mright, \colsize, \gutter \rangle,
\label{eq:page-definition}
\end{equation}
where:
\begin{itemize}
    \item $\Wpage \in \mathbb{R}^+$ and $\Hpage \in \mathbb{R}^+$ denote the  width and height of the page, respectively, measured in millimeters (mm).
    \item $\mtop, \mbottom, \mleft, \mright \in \mathbb{R}^+$ represent the  margins that restrict the usable layout space from the outer boundaries of the page.
    \item $\colsize \in \mathbb{R}^+$ represents the fixed width of each column in the page layout. 
    \item $\gutter \in \mathbb{R}^+$ denotes the spacing between columns. 
\end{itemize}
Consequently, the effective width (\Weff) and height (\Heff) of the page canvas are defined as $\Weff = \Wpage - \mleft - \mright$ and $\Heff = \Hpage - \mtop - \mbottom$.

    \centering
    \includegraphics[width=0.8\widthForOneImage]{img/page-with-notation.pdf}
    \caption{Page $\page$}
    \label{fig:page}
\end{figure}

\subsection{Web article ($\articleobj{i}$)}
\label{sec:web-article}

A web article $\articleobj{i} \in \articleset$ (\figref{fig:article}), where  $\articleset$ is a set of articles, is defined the following tuple:
\begin{equation}
\articleobj{i} = \langle \Cart{i}, \Nimg{i}, \Tlart{i}, \Stlart{i}, \Mainart{i} \rangle,
\end{equation}
where:
\begin{itemize}
    \item $\Cart{i} \in \mathbb{Z}^+$ represents the total character count of the body text,
    \item $\Nimg{i} \in \mathbb{Z}_{\ge 0}$ denotes the number of images that \articleobj{i}\ contains,
    \item $\Tlart{i} \in \{0, 1\}$ is a binary flag indicating the presence ($1$) or absence ($0$) of a headline or title element,
    \item $\Stlart{i} \in \{0, 1\}$ is a binary flag indicating the presence ($1$) or absence ($0$) of an accompanying subtitle,
    \item $\Mainart{i} \in \{0, 1\}$ is a binary flag indicating whether the article is designated as the main lead story ($1$) within the page context. Only one article per page can be indicated as main.
\end{itemize}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\widthForOneImage]{img/article-with-notation.pdf}
    \caption{Web article $\articleobj{i}$}
    \label{fig:article}
\end{figure}

\subsection{Template ($\templateobj{j}$)}
\label{sec:template}
Formally, an article template $\templateobj{j} \in \templatecatalog$ (\figref{fig:template}), where $\templatecatalog$ is a set of templates, is characterized as follows:

\begin{equation}
\templateobj{j} = \langle \Wtemp{j}, \Htemp{j}, \zoning{j}, \capacity{j} \rangle,
\end{equation}

where:
\begin{itemize}
    \item $\Wtemp{j} \in \mathbb{R}^+$ and $\Htemp{j} \in \mathbb{R}^+$ represent the  width and height of the template layout, respectively, measured in millimeters (mm). In the case of the page generation task (Chapter~\ref{chapter:pagegen}), $\Wtemp{j}$ strictly adheres to the horizontal column size $\colsize$ and gutter $\gutter$ defined by the page $\page$.
    \item $\zoning{j} = \{\zblock{j}{1}, \zblock{j}{2}, \dots, \zblock{j}{|\zoning{j}|}\}$ represents the zoning topology of the template, defined as a finite set of $|\zoning{j}|$ internal blocks. 
    Each block $\zblock{j}{k}$ is formalized as a pair
    $$\zblock{j}{k}= \langle \blockgeom{\zblock{j}{k}}, \blockfeat{\zblock{j}{k}} \rangle,$$
    where:
    \begin{itemize}
        \item $\blockgeom{\zblock{j}{k}}$ is an ordered set of cartesian coordinates (relative to $\templateobj{j}$ dimensions) that define the polygonal geometry of the block within the template layout.
        \item $\blockfeat{\zblock{j}{k}} \in \{\text{THEME}, \text{TITLE}, \text{SUBTITLE}, \text{PHOTO}, \text{CAPTION}, \text{TEXT}\}$ indicates the feature class assigned to the block.
    \end{itemize}
    Note that the image slots available (\Nimgmax{j}) is an implicit property derived from the zoning topology, such that $\Nimgmax{j} = |\{\zblock{j}{k} \in \zoning{j} : \blockfeat{\zblock{j}{k}} = \text{PHOTO}\}|$.

    \item $\capacity{j} \in (\mathbb{Z}^+)^{(\Nimgmax{j} + 1) \times 2}$\ is a text capacity matrix, which defines the body text capacity depending on the number of image slots kept for the print article. Note that this gives a single template the flexibility to accommodate a range of body text sizes by omitting some of its image slots. \melody adopted this design specifically to limit the size of the template catalog, since a single template can thereby serve several distinct configurations rather than requiring a dedicated template for each one.
    
    Formally, the text capacity matrix is defined by:
    \begin{equation}
        \capacity{j} =
        \begin{bmatrix}
        \capacity{j}[0, 0] & \capacity{j}[0, 1] \\
        \capacity{j}[1, 0] & \capacity{j}[1, 1] \\
        \vdots & \vdots \\
        \capacity{j}[\Nimgmax{j}, 0] & \capacity{j}[\Nimgmax{j}, 1]
        \end{bmatrix}
        \begin{array}{l}
        \leftarrow \text{0 active images} \\
        \leftarrow \text{1 active image} \\
        \\
        \leftarrow \Nimgmax{j} \text{ active images}
        \end{array}
    \end{equation}
where the elements in the $k$-th row denote the text capacity bounds when $k$ image slots are active, i.e., $k \leq \Nimgmax{j}$ image slots  are used to allocate an image. Specifically: %todo: add index active image 
\begin{itemize}
    \item $ \capacity{j}[k, 0]$ establishes the minimum character requirement,
    \item $ \capacity{j}[k, 1]$ defines the maximum character capacity.
\end{itemize}
These bounds are strictly determined by the area variations that occur when removing the $\Nimgmax{j} - k$ unused image slots from the template. Because the available image slots within a template may vary in physical dimensions (e.g., a large main photograph versus smaller secondary images), omitting different combinations of slots yields varying amounts of reclaimed space for the text block. Consequently, the minimum capacity $\capacity{j}[k, 0]$ is computed by assuming the omission of the smallest available photo slots (resulting in the least amount of expanded text area), whereas the maximum capacity $\capacity{j}[k, 1]$ is computed by omitting the largest available photo slots (yielding the maximum possible text area).

Note that the proposed formulation only assesses template suitability rather than determining which specific images to discard, leaving that selection decision to the human designer or external editorial software.
\end{itemize}

    \caption{Template $\templateobj{j}$}
    \label{fig:template}
\end{figure}


\subsection{Print article}
When an article $\articleobj{i}$ is formatted to be placed in the page canvas, it means that an individual template $\templateobj{j} \in \templatecatalog$ has been assigned to $\articleobj{i}$, becoming a print article (\figref{fig:print-article}).

To formalize this, \templatesel{i} denotes the index of the selected template $\templateobj{\templatesel{i}} \in \templatecatalog$ for article $\articleobj{i}$. Formally,
\begin{equation}
\templatesel{i} \in \{1, 2, \dots, \catalogsize\}, \forall i \in \{1, 2, \dots, \numarticles\}.
\label{eq:template-selection-def}
\end{equation}

Note that after this selection, the article acquires the physical dimensions and characteristics of the assigned template. 
Additionally, the number of images $\Nimg{i}$ in the article fixes the number of active image slots in the template, which in turn determines the text capacity range $[\capacity{\templatesel{i}}[\Nimg{i}, 0], \capacity{\templatesel{i}}[\Nimg{i}, 0]]$ to respect in the optimization process.

\end{figure}

\subsection{Full page layout $\solution$}
\label{sec:solution}

A solution $\solution$ corresponds to the desired output of the web-to-print workflow. It is defined as a fully composed page layout in which every article $\articleobj{i} \in \articleset$ is assigned a template $\templateobj{\templatesel{i}}$ and is positioned within the physical boundaries of the page $\page$ (\figref{fig:solution}).
\begin{figure}[htbp]

    \caption{Solution $\solution$: a full page $\page$ with three print articles positioned.}
    \label{fig:solution}
\end{figure}



\section{Industrial Datasets}



To validate and benchmark the computational frameworks developed in this thesis, empirical evaluations rely on two real-world industrial repositories provided by press publishers operating under the \melody CMS environment. These datasets encapsulate different levels of editorial abstraction, ranging from individual article template catalogs with historical usage logs to fully assembled multi-article newspaper spreads.
